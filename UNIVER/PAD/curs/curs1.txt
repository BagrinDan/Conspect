    > RFC:
        1. Фундамент Веба и протокола HTTP

            * RFC 7230 — RFC 7235 (заменены на RFC 9110 / 9112)
            Что это: Библия для любого веб-разработчика. 
            Они описывают синтаксис сообщений HTTP/1.1, методы (GET, POST, PUT, DELETE), 
            заголовки, коды состояния (200, 404, 500 и т.д.), а также механизмы кэширования и аутентификации.  

            * RFC 7540
            Что это: Стандарт HTTP/2. 
            Описывает бинарный протокол, мультиплексирование (несколько запросов по одному TCP-соединению)
            и сжатие заголовков HPACK.  

            * RFC 3986
            Что это: Единый стандарт структуры URI (Uniform Resource Identifier) и URL. 
            Именно этот документ строго определяет, как должны выглядеть ссылки, какие символы можно экранировать (процентами вроде %20), а какие — нет.

        2. Безопасность и Сеть (Transport & Security)
            * RFC 793
            Что это: Классический и великий документ, описывающий протокол TCP (Transmission Control Protocol). 
            Вся надежная доставка данных в интернете построена на принципах трехстороннего рукопожатия (Three-way handshake), описанных здесь.  
                
            * RFC 8446Что это: Протокол TLS 1.3 (Transport Layer Security). Главный стандарт шифрования в современном интернете, обеспечивающий работу HTTPS.                 Он сделал соединения не только безопаснее, но и значительно быстрее (упростил процесс рукопожатия).
                 
            * RFC 1034 и RFC 1035Что это: Основа DNS (Domain Name System). 
            Документы описывают, как имена сайтов (например, google.com) преобразуются в IP-адреса и как устроена иерархия серверов имен.
            
        3. Архитектура API и Форматы данных
            * RFC 8259 
            Что это: Официальная спецификация формата JSON (JavaScript Object Notation). 
            Да-да, любимый всеми формат обмена данными в API тоже стандартизирован на уровне IETF.
                
            * RFC 7807
            Что это: Стандарт для Problem Details for HTTP APIs. 
            Очень полезная вещь при проектировании REST API: он описывает единый формат, в котором сервер должен возвращать ошибки (чтобы клиент сразу понимал, каков статус, заголовок и детальное описание проблемы в JSON или XML).
                
        4. Знаменитые «Первоапрельские» RFC (Easter Eggs)
            Инженеры IETF обладают отличным чувством юмора. 
            Каждый год 1 апреля они публикуют шуточные RFC, которые оформлены по всем правилам серьезных стандартов, но описывают абсурдные вещи. 
                
            Самые легендарные:
            RFC 1149 (Standard for the transmission of IP datagrams on avian carriers): Передача IP-пакетов с помощью... 
            почтовых голубей (в 2001 году энтузиасты даже успешно провели такой пинг-тест с реальным пакетом данных!).
                
            RFC 2324 (Hyper Text Coffee Pot Control Protocol - HTCPCP/1.0): Протокол управления... кофейниками через HTTP. 
            В нем описаны шуточные методы вроде BREW (варить кофе) или POST (долить молока), а также легендарный код ошибки 418 I'm a teapot («Я — чайник»), который до сих пор официально поддерживают многие веб-фреймворки и разработчики браузеров в качестве пасхалки.
