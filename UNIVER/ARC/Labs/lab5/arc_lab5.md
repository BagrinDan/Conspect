
**SLAAC -** технология которая позволяет клиенту самому сгенерировать себе **IPv6**

**EUI-64** - алгоритм который берет 48-битный **MAC-адрес** и программно расширяет его до 64 бит (разрезает пополам, вставляет в середину `ff:fe` и инвертирует один седьмой бит).

**IPv6 - (128 biti)** - пример:
	**2001:0db8:85a3:0000:0000:8a2e:0370:7334** -> **2001:db8:85a3::8a2e:370:7334**

**IPv6** **GUA** *(Global Unicast Address*) - имеет два типа:
	- **==🟠Stateful==**: есть сторонее устройства которое раздаёт айпи
		* ***DHCPv6 Server*** - клиент получает айпи от **DHCPv6** и получает сообщение **RA** с флагом (*M = 1*, *Managed Address Configuration*).
	- **==🟢Stateless==**: нет стороннего устройства который бы раздавал айпи 
		* ***SLAAC*** - роутер отправляет сообщение **RA** в которое указан префикс сети 
			например 2001:db8:1::/64, а клиент сам формирует вторую часть через алгоритм **EUI-64**. Отправляет **RA** с флагом (*A = 1, Autoconfiguration*) 
		* ***SLAAC*** **with DHCPv6 Server** - клиент сам создает свой **ipv6** через **SLAAC**,
			но активно запрашивает dns, доменные имена и так далее. Роутер отправляет **RA** (*o = 1, Other Config*).

**NDP** (*Neighbor Discovery Protocol*) - аналог **ARP** для сетей **IPv6**. Данный протокол  работает поверх **ICMPv6** для нахождения роутеров или **DHCPv6** серверов.
- **RA** (*Router Advertisement*) **ответ роутера** - сообщения которое отправляет роутер чтобы дать понять сети как клиент получил свой ipv6.
- **RS** (*Router Solicitation*) **запрос клиента** - как только устройство подключается к сети он отправляет Multicast запрос на адрес `ff02::2`. Данный адрес только маршрутизаторы.

**NS** (*Neighbor Solicitation*) - служебное сообщение протокола ICMPv6 (тип 135) которое является запрос соседа
* ***DAD** *(Duplicate Address Detection)* - это встроенный защитный механизм протокола IPv6, который гарантирует, что в одном сегменте сети не появится два одинаковых IP-адреса.  
* **NUD** (*Neighbor Update Detection*) - отправляет периодически **NS** запросы 
* **Поиск MAC адреса** - 
**NA** (*Neighbot Answer*) - служебное сообщение протокола **ICMPv6** (тип 135) которое является ответом соседа. 

Этапы подключения **Stateful / DHCPv6**:
	1. Клиент подключается к сети и отправляет multicast запрос **RS** на `ff02::2` 
	2. Роутер отвечает **RA** с флагом M = 1
	3. Клиент понимает что нельзя самому создать себе айпи и отправляет запрос на получения айпи на `ff02::1:2`
	4. **DHCPv6** принимает запрос и отправляет айпи

Этапы подключения **Stateles**:
	1. **SLAAC**:
		1. Клиент подключается к сети и отправляет multicast запрос **RS** на `ff02::2` 
		2. Роутер отвечает **RA** с флагом A = 1
		3. Клиент берет префикс сети полученый от сети (первые 64 бита) и дописывает к нему свой идентификатор интерфейса (вторые 64 бита генерятся через рандомное число или на основе MAC адрес через EUI-48)
		4. Проверка уникальности через **DAD**. Клиент отправляет **NS** чтобы убедится что такого айпи нет.
		5. Настройка link-local. Клиент извлекает Link-local адрес роутера (из пакета RA) и прописывает его как шлюз по уполчанию
	2. **SLAAC + DHCPv6**:
		1. **Запрос маршрутизатора (RS):** Клиент отправляет запрос на `ff02::2`.
		2. **Ответ маршрутизатора (RA):** Роутер присылает сообщение с префиксом сети, но флаги выставлены иначе: **M=0** (генерируй IP сам), а **O=1** (Other configuration — в сети есть DHCPv6-сервер с дополнительными настройками, обратись к нему).
		3. **Генерация IP-адреса:** Клиент формирует свой IPv6-адрес (префикс от роутера + свой идентификатор).
		4. **Проверка уникальности (DAD):** Клиент проверяет адрес на конфликты.
		5. **Настройка шлюза:** Клиент записывает адрес роутера как шлюз по умолчанию.
		6. **Поиск сервера (Information-Request):** Увидев флаг O=1, клиент отправляет multicast-запрос к DHCPv6-серверам на адрес **`ff02::1:2`**. Так как IP-адрес ему уже не нужен, он отправляет специфический тип запроса — Information-Request (дай только дополнительные опции).
		7. **Ответ сервера (Reply):** DHCPv6-сервер получает запрос и отправляет клиенту список DNS-серверов и другие сетевые параметры. При этом сервер не фиксирует клиента в своей базе выданных адресов (поэтому режим называется Stateless DHCPv6).
