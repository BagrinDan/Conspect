====================
[тип] Посетитель
====================

===============
--Определения--
===============

    > Посетитель - поведенческий паттерн, который позволяет добавлять новые операции над объектами структуры, 
    не изменяя сами классы этих объектов

====================
--Основные понятия--
====================

    > Client - 

    > IVisitor<<Interface>> - интерфейс посетителей. Каждый метод для каждого Concrete Element

    > ConcreteVisitor:

    > Element<<interface>> - интерфейс который определяет метод accept(IVisitor visitor)
     
    > Concrete Element - классы которые имплементят интерфейс Element:


==========================
-- Случаи использования --
==========================

    - Паттерн Посетитель используется тогда, когда нам нужно добавить новые внешние методы 
      (операции) для группы элементов, не изменяя при этом код самих элементов.

======================
-- Ключевые моменты --
======================

    > [Concrete Element]:

            @Override
            public void accept(Visitor visitor) {
                visitor.visit(this);
            }

    > [Concrete Visitor]:

            @Override
            public void visit(Coffee coffee) {
                double taxPrice = coffee.getPrice() - 0.10;
                System.out.println("Product is Coffee. Initial price for " + coffee.getName() + " is " + coffee.getPrice() + ", with taxes is " + taxPrice);
            }
 

==================
--Принципы Солид--
==================

    > SRP - каждый посетитель имеет одну ответсвенность
    > OCP - можно добавлять новых посетителей не модифицируя код
    > LSP - наблюдатели могут заменить родительский класс без нарушения логики 

================
--Плюсы Минусы--
================

    Плюсы:
        - позволяет разделить внутрение методы от внешних

    Минусы:
        - Ситуативный паттерн, его добавления куда попало может усложинить систему
