====================
[поведенческий] Chain of resp
====================

===============
--Определения--
===============

    > Chain of resp -это поведенческий паттерн, который позволяет передавать запрос по цепочке обработчиков, 
    пока один из них не обработает его.

====================
--Основные понятия--
====================

    > Abstract Handler - абстрактный обработчик, который хранит ссылку на следующий Handler и определяет общий интерфейс обработки.

    > Handler - конкретный обработчик 

==========================
-- Случаи использования -- 
==========================

    - Когда нужно провести цепочную валидацию реквеста

======================
-- Ключевые моменты --
======================

    
    public abstract class Handler {
        // 1. Ссылка на следующтй хэндлер
        Handler next;


        // 2. Сеттер
        public Handler setHander(Handler next){
            this.next = next;
            return next;
        }
        

        // 3. Методы обрабодки
        public abstract boolean handle(String login, int password, String status);
        

        // 4. Передача следующему хэндлеру
        public boolean handleNext(String login, int password, String status){
            if(next == null){
                return true;
            }
            return next.handle(login, password, status);
        }
    }

==================
--Принципы Солид--
==================

    (не нарушает)
        > SRP - каждый [Handler] имеет свою ответсвенность
        > OCP - можно добавлять новые Handler без изменения существующего кода
        > LSP - [Concrete Handler] может использоваться вместо [Abstract Handler]
        > ISP - Handler обычно содержит минимальный интерфейс обработки
        > DIP - Handlers работают через абстракцию

    (Нарушает)

================
--Плюсы Минусы--
================

    Плюсы:
        - снижает связанность между отправителем и обработчиками
        - легко добавлять новые обработчики без изменения существующего кода
        - удобно строить pipeline обработки
        - позволяет разделять ответственность между независимыми шагами
    
    Минусы:
        - сложно отследить путь запроса по цепочке
        - порядок обработчиков критически важен
        - длинные цепочки ухудшают производительность
