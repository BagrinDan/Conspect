CI/CD это конвейер, который отвечает за непрерывный путь кода от компьютера разработчика до состояния 
готовности к работе (или до самого продакшена).
Где: CI - про проверку и сборки кода
     CD - про его доставку на сервер и дальнейшего деплоя

    > Kubernetes (база)
        > Master Node - центр принятия решении
            ------- Control Panel -------
            - etcd - база данных формата ключ/значение. По типу Redis/MongoDB
            - scheduler - определяет на какой ноде стоит лучше задеплоить приложение
            - controller manager - процесс который следит чтобы заданные действия были сделанныku
            - api server - точка входа через который общаются и процессы k8s и разработчики
            -----------------------------

        > Worker Node - один сервер где находятся приложения

        > Deployment - манифест в котором мы описывает декларативно что нам надо. Занимается обновлением и откатами
            - Replica set 
            - Pod - это приложение (контейнер)
            - KubeProxy - определяет на какой pod пойдет запрос
            - kubelet - проверяет если пода жива

Scripting 
    bash > 
        $0	Имя самого скрипта (например, ./script.sh)
        $1, $2, $3	Первые три аргумента
        $#	Количество переданных аргументов
        $@	Все аргументы списком (сохраняет кавычки внутри)
        $?	Код возврата последней выполненной команды (0 = успех, !0 = ошибка)
        $$	PID (ID процесса) текущего скрипта

        -f = проверяет если это файл и он существует
        -d = проверяет если это директория и он существует
        -e = объект существует (файл, папка, сокет, ссылка)
        -s = объект сущесвует и он не пустой

        -z = длинна строки равна нулю
        -n = длинна не равноа нулю

        -eq = Equal
        -ne = not equal
        -gt = greater than
        -ge = greater or equal
        -lt = less than
        -le = less or equal
