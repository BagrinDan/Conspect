

    > HTTP 0.9 (1991)

        Открывалось TCP соединение и клиент отправлял get запрос и получал голый html.
        Проблема: 
            - Не имел заголовков запроса и ответа;
            - Поддерживал только GET;
            - Нельзя было передавать метаданные; 
            - Нельзя было отправлять ничего кроме HTML;
            - Не существовало кодов состояния (200, 404, 500 и так далее);
            - Сервер не мог сообщить причину ошибки


    > HTTP 1.0 (1996)

        Добавили: 
            > Header - теперь можно было отправлять мета данные:
                статус кода, content type 
            > MIME и Content type - теперь можно отправить не только текст, но и скрипты, графику, файлы
            > Новые методы: 
                            - HEAD: как GET но без тела ответа
                            - POST: создания 

        Проблема: Для каждого запроса открывалась новая TCP соединение и закрывала сразу после получение ответа


    > HTTP 1.1 (1997-1999)

        Добавили:
            > Новые методы: 
                            - PUT - полная замена
                            - DELETE - удалить
                            - OPTIONS - запрос, чтобы понять какие методы запрашивает сервер
                            - CONNECT - туннель для HTTPS через прокси
                            - TRACE - запрос который отправляется клиенту для диагностики

            > Больше TCP не закрывалось после получения одного ответа за счет keep alive
                - Keep alive - это механизм, при котором одно TCP-соединение используется для нескольких HTTP-запросов и ответов, 
                вместо создания нового соединения для каждого запроса.
            > Pipelining - клиент может отправить несколько HTTP-запросов подряд, не дожидаясь ответов
            > Chunking transer - отправлять данные кусками
            > Etag - возможность клиента понять если полученный файл изменился, чтобы не скачивать его повторно

        Проблемы:
            Application HOL Blocking (Блокировка на уровне приложения):
                - из-за pipelining один медленный запрос блокирует очередь;
                - всё идёт строго последовательно

            Огромные заголовки
                - они отправляются каждый раз заново
                - нет сжатия заголовков 

            TCP-level HOL blocking

    > HTTP 2 Эра Мультиплексирования

        Добавили:
            > Бинарный протокол: HTTP/2 перестал быть текстовым. 
            Данные теперь упаковываются в компактные бинарные фреймы. Их легче и быстрее парсить компьютерам.

            > Мультиплексирование: Главная киллер-фича. Теперь внутри одного TCP-соединения браузер открывает сотни параллельных потоков (Streams). 
            Кусочки картинок, стилей и скриптов летят одновременно вперемешку. Блокировка очереди на уровне приложения (HTTP HOL) была побеждена.

            > HPACK (Сжатие заголовков): Заголовки сжимаются по специальному алгоритму, 
            а сервер и клиент помнят прошлые заголовки и не пересылают их повторно, если они не изменились.

            > Server Push: Сервер может упреждающе отправить клиенту файлы (например, CSS-стили), 
            которые клиент еще даже не запросил, но они ему точно понадобятся для рендеринга страницы.

        Проблема:
            Главная проблема (Транспортный HOL):
            Убрав блокировку на уровне HTTP, инженеры уперлись в ограничения самого TCP. 
            Поскольку для всех потоков используется один TCP-канал, потеря хотя бы одного IP-пакета на линии 
            (например, из-за сбоя Wi-Fi) приводила к тому, что TCP-стек операционной системы замораживал вообще все потоки и ждал переотправки потерянного пакета.
    
    
    > HTTP 3

        Добавили:
        > Переход на UDP и QUIC: HTTP/3 работает поверх протокола QUIC, который, в свою очередь, работает поверх быстрого UDP.

        > QUIC-потоки: Логика независимых потоков спустилась с уровня приложения на транспортный уровень. 
        Если сейчас потеряется пакет, относящийся к Картинке №1, QUIC запросит его повтор, но Картинки со 2-й по 10-ю продолжат скачиваться без единой задержки. 
        Проблема Head-of-Line Blocking решена окончательно.

        > Молниеносный коннект (0-RTT): Handshake для установки соединения и TLS-шифрования теперь объединены в один шаг. 
        Если браузер уже подключался к этому серверу ранее, он может начать слать данные вообще сразу, без предварительных рукопожатий (0-RTT).

        > Connection Migration (Миграция соединения): В TCP твое соединение привязано к цепочке "Твой IP + Твой порт + IP сервера + Порт сервера". 
        Если ты вышел из дома, Wi-Fi отключился и телефон прыгнул на LTE — твой IP изменился, и все TCP-сессии (скачивания файлов, звонки) обрывались. 
        В QUIC соединение привязано к уникальному Connection ID. Ты можешь переключаться между сетями бесшовно — закачка не прервется ни на долю секунды.
