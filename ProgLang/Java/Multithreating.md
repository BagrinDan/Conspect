3. Блокировки (java.util.concurrent.locks)

Гибкая альтернатива ключевому слову synchronized с возможностью таймаутов, прерываний и разделения доступа.

    ReentrantLock: Явная блокировка с поддержкой таймаутов (tryLock()), честной очереди (fairness) и возможностью прерывания.

    ReentrantReadWriteLock: Разделяет доступ на чтение и запись. Множество потоков могут читать параллельно, но запись выполняется монопольно.

    StampedLock: Оптимистичная блокировка с высокой производительностью для сценариев с частым чтением и редкой записью.

    Condition: Аналог методов wait() / notify() у объектов, привязанный к конкретному экземпляру Lock.

4. Синхронизаторы и координация (java.util.concurrent)

Готовые механизмы для синхронизации работы группы потоков.

    CountDownLatch: Заставляет один или несколько потоков ждать, пока не завершится определенное количество операций в других потоках (одноразовый «таймер»).

    CyclicBarrier: Точка сбора для группы потоков. Все потоки ждут, пока каждый из них не дойдет до барьера, после чего продолжают работу (многоразовый).

    Semaphore: Ограничивает количество потоков, которые могут одновременно получить доступ к ресурсу (управление пулом доступов через токены).

    Exchanger: Точка встречной передачи данных между двумя потоками.

    Phaser: Продвинутый аналог CyclicBarrier для фазовой синхронизации с динамическим изменением числа участников.

5. Потокобезопасные коллекции (Concurrent Collections)

Оптимизированные структуры данных, заменяющие классические ArrayList, HashMap и т.д.

    ConcurrentHashMap: Потокобезопасная хэш-таблица без полной блокировки (использует сегментирование и CAS).

    CopyOnWriteArrayList / CopyOnWriteArraySet: Коллекции, которые при любом изменении создают полную копию массива. Идеальны для частых чтений и редких записей.

    Блокирующие очереди (ArrayBlockingQueue, LinkedBlockingQueue, PriorityBlockingQueue): Используются в шаблоне «Производитель — Потребитель» (Producer-Consumer).

    ConcurrentLinkedQueue / ConcurrentSkipListMap: Высокопроизводительные неблокирующие очереди и карты на базе CAS.

6. Управление потоками и пулы (Executor Framework)

Инструменты для эффективного переиспользования потоков вместо постоянного создания через new Thread().

    ExecutorService: Интерфейс для управления пулом рабочих потоков.

    Executors: Фабричный класс для создания популярных пулов:

        newFixedThreadPool(n) — фиксированное количество потоков.

        newCachedThreadPool() — расширяемый пул с повторным использованием свободных потоков.

        newSingleThreadExecutor() — один фоновый поток.

        newScheduledThreadPool(n) — для выполнения задач по расписанию или с задержкой.

    ForkJoinPool: Специализированный пул для рекурсивных задач по принципу «Разделяй и властвуй» (Work-Stealing алгоритм).

7. Работа с результатами и асинхронность

Средства для получения результатов выполнения из других потоков.

    Callable<V>: Аналог Runnable, но умеет возвращать результат или выбрасывать исключения.

    Future<V>: Объект-контейнер для ожидания и получения результата асинхронной задачи.

    CompletableFuture<V>: Мощный инструмент для декларативного асинхронного программирования (поддерживает цепочки вызовов thenApply(), thenCombine(), обработку ошибок и объединение задач).

8. Локальное состояние потоков (Thread Local Storage)

    ThreadLocal<T>: Создает изолированную копию переменной для каждого потока. Потоки не делят данные между собой, что полностью исключает race condition (например, для SimpleDateFormat или соединений с БД).

    InheritableThreadLocal<T>: Передает значения ThreadLocal от родительского потока к дочернему при его создании.
