## Общая инфа:

- **SSH** (*Secure Shell*) - протокол общения между двумя узлами путём шифрования
- **Порт**: 22
- **Использует**: TCP
- **OSI**: 7 Приложения (Application)
- **TCP/IP**: 4 Приложения (Application)

-----------------

## **Инициализация:**

1. При вводе `ssh admin@192.168.1.1` клиент и сервер договариваются об базе (*5*) и об ограничителе *(23)*.
2. Клиент создает свое рандомное число (*6*) и взодит базу в степень этого числа: *Например: 5^6 = 15625 % 23 = **8***
3. Сервер создает свое рандомное число (15) и взодит базу в степень этого числа: *Например: 5^15 = 30.517.578.125 % 23 = **19***
4. Оба отправляют свои получившиеся числа: ***8 и 19***. Хакер видит числа 8 и 19. Но он не знает, в какую степень нужно было возвести базу (5), чтобы получить эти остатки.
5. Клиент берет число сервера (19) и взодит в степень свеого секрета (6): Получается 19^6 = 47.045.881 % 23 = 2
6. Сервер берет число клиента (8) и взодит в степень своего секрета (15):
   Получается 8^15 = 35.184.372.088.832 % 23 = 2

-----------------------
## **Безопасный тунель:**

Теперь число 2 используется как симетричный ключ для шифрование сообщения

-----------------------

## **Аутентификация**

1. Серверу нужно понять если это клиент а не хакер. Для этого он отправляет ему число.
2. Клиент подписывает его используя свой приватный ключ
3. Если всё правильно то сервер при проверки подписи публичным ключом получит тоже самое число
